# 변환 예시 (Before → After)

## 예시 1 — 일반 산문 → 개조식 마커형(A)

**Before (만연체 초안)**

> 최근 인공지능 기술이 빠르게 발전하면서 우리 기관에서도 업무에 AI를 도입해야 한다는 목소리가 커지고 있다. 하지만 막상 도입하려고 하면 어떤 업무에 적용할지, 데이터는 쓸 수 있는지, 비용은 얼마나 드는지 확인할 것이 많다. 그래서 내부에 TF를 만들어 차근차근 검토해보려고 한다.

**After (개조식 마커형)**

```
□ 추진 배경
  ○ (정책 환경) 인공지능 기술의 빠른 발전으로 기관 내 AI 도입 요구가 증가하고 있음
  ○ (검토 과제) 적용 업무 선정, 데이터 활용 가능성, 소요 비용 등 사전 확인 사항이 다수 존재함
  ○ (추진 방향) 내부 TF를 구성하여 단계적으로 도입 가능성을 검토하고자 함
```

핵심 변화: 만연체→명사형 종결, 두괄식 괄호 표제, 감정 표현("목소리가 커지고") 제거, 정보는 모두 보존. "검토하고자 함"처럼 의지 표현은 "함"을 유지하되, 단순 동작명사는 "함" 없이 끝냄("도입 가능성을 검토").

---

## 예시 2 — 같은 내용 → 마크다운형(B)

마크다운형에서도 **괄호 표제를 유지**하고, 동작명사 뒤 불필요한 "함"은 붙이지 않는다.

```markdown
## 1. 추진 배경

- **(정책 환경)** 인공지능 기술의 빠른 발전으로 기관 내 AI 도입 요구가 증가하고 있음
- **(검토 과제)** 적용 업무 선정, 데이터 활용 가능성, 소요 비용 등 사전 확인 사항이 다수 존재함
- **(추진 방향)** 내부 TF를 구성하여 단계적으로 도입 가능성을 검토
```

## 예시 3 — 정형 내용은 표로 (재구현)

**Before**

> 일반 과제는 내부 문서 정리나 공개자료 분석처럼 민감하지 않은 일이라 TF가 자체 검토하면 되고, 내부 운영자료를 쓰는 과제는 TF장 승인을 받아야 하며, 1년 넘게 쓰거나 외부에 공개하는 과제는 기존 공식 절차로 넘겨야 한다.

**After (표)**

| 구분 | 대상 | 승인 방식 |
|------|------|-----------|
| 일반 과제 | 내부 문서 정리, 공개자료 분석 등 비민감 업무 | TF 내부 검토 |
| 내부자료 활용 과제 | 내부 운영자료 활용 | TF장 승인 |
| 공식 전환 과제 | 1년 이상 사용, 외부 공개 | 기존 공식 절차 전환 |

서술형 나열을 표로 옮기면 비교·검토가 쉬워지고, 결재선에서 빠르게 판단 가능함.

## 1. 문체 규칙 전문

- **명사형 종결** — `~함, ~음, ~필요, ~예정, ~검토, ~추진, ~마련, ~확보`. 평서형 종결(`~한다, ~된다, ~이다, ~있다, ~하였다`)을 쓰지 않음.
- **불필요한 "함" 제거 (중요)** — 한자어 동작명사(검토·활용·마련·확인·예방·운영·추진·선정·수행·기록·제공·담당·제한·판단·구체화·조정·전환·발굴 등)는 뒤에 "함"을 붙이지 않고 **명사로 끝냄**. "검토함→검토", "활용함→활용", "마련함→마련", "예방함→예방", "확인함→확인". 이미 명사가 종결 기능을 하므로 "함"은 군더더기임. 단, "~하고자 함", "~되도록 함", "~수 있음", "~필요", "~있음/없음", "~임" 등 명사로 환원되지 않는 형태는 그대로 둠.
- **두괄식 구성** — 주제를 먼저 명기하고 부연을 뒤에 둠. 중주제(○) 텍스트는 반드시 `(괄호 주제)`로 시작. 예: `(현황) …`, `(문제점) …`, `(개선방안) …`.
- **객관적 관찰자 시점** — 1인칭·감정·수사 배제. "우리는", "매우", "혁신적", "반드시 ~해야 한다는 점에서 의미가 큼" 등 지양. 사실과 판단을 건조하게 진술.
- **간결성** — 한 항목은 한 논점. 접속사·군더더기("그리고", "또한 ~인 측면에서") 최소화.
- **내용 보존** — 수치·고유명사·일자·사례·근거를 전량 유지. 요약·축소·삭제 금지.

## 2. 불릿 위계와 마커 (개조식 마커형 = A)

```
□ 대주제 (섹션 제목 성격)
  ○ (중주제) 두괄식 괄호로 시작하는 핵심 진술
    - 소주제
      * 세부 항목
        ** 최세부 항목
```

- 들여쓰기는 단계마다 2칸(또는 한글에서 1수준)씩.
- ○ 레벨은 예외 없이 `(주제)`로 시작.
- 번호가 필요한 절차·순서는 `①②③…` 또는 `1. 2. 3.` 사용.

## 3. 마크다운형 대응 규칙 (B)

| 개조식 마커 | 마크다운 대응 |
|------|------|
| □ 대주제 | `## n. 제목` (또는 `###` 하위 섹션) |
| ○ (중주제) 내용 | `- **(중주제)** 내용` (괄호 표제 유지, 굵게) |
| - 소주제 | 중첩 `  - 소주제` |
| * 세부 | 중첩 `    - 세부` |
| 절차/순서 | 번호 리스트 `1. 2. 3.` 또는 코드블록 흐름도 |
| 표 | 표준 마크다운 표 |

- 문서 상단에 제목(H1) + 메타(작성/일자/성격) + **핵심 요약** 3줄 이내.
- 명사형 종결은 마크다운형에서도 동일하게 유지(형식만 바뀌고 문체는 불변).

## 4. 표 작성 규칙

정형화 가능한 내용(대상·기준·역할·일정·지표 등)은 산문보다 표를 우선.

- **formal** — 굵은 외곽선 + 헤더 음영 + 이중선 구분. 결재·제출용 핵심 표.
- **simple** — 가는 균일선 + 헤더 음영만. 참고·부속 표.
- 마크다운형에서는 표 캡션을 `〈표 n〉 제목` 또는 표 바로 위 굵은 줄로 표기.
- 헤더는 명사구, 셀 내용도 명사형/명사구로 통일.

## 5. (C) JSON 브리프 스키마

다운스트림(HWPX/HTML 등) 자동 렌더링이 필요할 때 사용.

```json
{
  "type": "brief",
  "title": "보고서 제목",
  "team": "작성 팀명(추정 가능)",
  "date": "2026.02.20.(목)",
  "summary": ["◈ 핵심 요약 1", "◈ 핵심 요약 2"],
  "sections": [
    {
      "title": "섹션 제목 (□ 마커 제외, 텍스트만)",
      "items": [
        { "level": "○", "text": "(중주제) 마커 제외, 텍스트만" },
        { "level": "-", "text": "소주제" },
        { "level": "*", "text": "세부 항목" },
        { "level": "**", "text": "최세부 항목" }
      ]
    }
  ],
  "tables": [
    {
      "after_section": 0,
      "style": "formal",
      "title": "표 제목",
      "headers": ["열1", "열2", "열3"],
      "rows": [["값1", "값2", "값3"]]
    }
  ],
  "references": [
    {
      "label": "참고1",
      "title": "참고 제목",
      "items": [
        { "level": "□", "text": "대주제", "bold": true },
        { "level": "○", "text": "(내용) 상세 설명" }
      ]
    }
  ]
}
```

JSON 출력 규칙(엄수):
- `tables.rows`의 모든 셀은 숫자라도 **문자열**로 출력. 예: `["항목", "22", "45.8"]`.
- `items[].level`은 `"○", "-", "*", "**"` 중 하나만(섹션 본문에서는 `"□"` 사용 불가, 섹션 제목이 □ 역할).
- `level`을 빈 문자열로 두지 않음(항목 누락 원인).
- `sections[].title`에 □ 마커를 넣지 않음(렌더러가 자동 부착).
- `items[].text`에 레벨 마커(○, -, * 등)를 넣지 않음.
- 날짜 형식 `YYYY.MM.DD.(요일)`.
- 제목·작성부서·일자는 원문에서 추출하되 없으면 추정.
- `summary`는 1~3줄, 각 앞에 `◈`.
- JSON만 출력(설명 텍스트·코드펜스 금지).

## 6. 종결 변환 사전 (만연체 → 명사형)

| 만연체 | 명사형(개조식) |
|------|------|
| ~한다 / ~하고 있다 | ~함 |
| ~된다 / ~되고 있다 | ~됨 |
| ~이다 | ~임 |
| ~있다 / ~없다 | ~있음 / ~없음 |
| ~해야 한다 | ~필요 / ~하여야 함 |
| ~하고자 한다 | ~하고자 함 |
| ~할 것이다 / ~할 예정이다 | ~예정 |
| ~하였다 / ~했다 | ~함 / ~완료 |
| ~할 수 있다 | ~가능 / ~할 수 있음 |
| ~하는 것을 목적으로 한다 | ~을 목적으로 함 |
| ~검토하기로 하였다 | ~검토 예정 |
